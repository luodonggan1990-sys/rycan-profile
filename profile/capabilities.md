# 职业能力与企业 AI 应用需求对照

最后更新：2026-11-27。

核心主线：过去不同阶段的能力，有机会围绕同一个企业问题共同发挥作用。不是将履历直接等同于已经具备每一项交付能力，而是明确经验基础、应用位置和仍需验证的部分。

## 经历与企业问题

| 经历基础 | 企业推进 AI 需要回答的问题 | 可发挥的作用 |
| --- | --- | --- |
| 研发 | 流程怎样进入系统？现有应用如何接入？ | 理解业务规则、技术实现与系统集成 |
| 数据集成、BI、大数据 | 数据在哪里？质量、口径和访问条件如何？ | 梳理数据基础、加工与分析链路 |
| 产品经理 | 客户真正需要什么？哪些场景值得先做？ | 需求判断、场景选择与产品取舍 |
| 技术售前 | 方案能否被理解？怎样协调各方推进？ | 方案表达、沟通与协作 |
| 云解决方案架构 | 应用如何部署？资源、稳定性、安全和成本如何平衡？ | 连接基础设施、平台服务与应用架构 |
| 训练客户、推理与 AI Infra 场景 | 模型服务如何可用、稳定且成本可接受？ | 从实际客户场景理解模型运行条件与约束 |
| Agent 与 Harness 持续实践 | 任务怎样持续执行、恢复状态、检查结果并交由人判断？ | 关注任务组织、工具调用、状态、反馈与人工接手 |
| MBA 学习 | 为什么投入？现在值不值得做？如何判断效果？ | 引入经营、组织和投入产出的视角 |

## 企业整体 AI 能力分层

以下为规划与沟通框架，不是严格的产品依赖栈，也不代表 Rycan 在每一层都从事过研发。

| 层次 | 需要对照的企业基础 | 主要问题 |
| --- | --- | --- |
| 经营目标与价值 | 经营目标、预算和效果判断 | 要解决什么问题，怎样验收价值？ |
| 业务流程与协作 | 物流、信息流、资金流，以及岗位和人员协作 | 哪些任务适合 AI，谁负责判断和承接？ |
| Agent 任务执行 | 任务、上下文、工具、状态、反馈 | 怎样处理复杂任务、异常和人工接手？ |
| 信息系统与集成 | 现有业务系统、接口与权限 | 如何接入、执行动作并保留审计？ |
| 数据与分析 | 数据源、质量、治理与决策系统 | 数据是否可用，输出是否可信？ |
| 模型与 AI 平台 | 训练、推理、模型服务与评估 | 如何选型、运行、评估与持续维护？ |
| 云与算力基础 | 芯片和计算资源、云服务与平台 | 资源、稳定性、安全和成本能否支撑？ |

芯片是算力基础的一部分，不据此推断芯片设计、底层硬件研发或全层技术专家身份。权限、安全、成本、人员协作、评估与维护贯穿各层。

## 希望推进的落地路径

梳理问题和现有条件 → 选择具体、有价值的场景 → 小范围试点 → 共同验证效果 → 决定迭代、扩展或停止 → 沉淀可复用的产品与服务。

这是一条实践路径，具体交付范围、验收、费用及责任边界需按项目确认。标杆案例仍在孵化，当前不列未确认的客户成果或 ROI 数据。
